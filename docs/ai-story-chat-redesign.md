# AI 重构方案：剧情引入 + AI 自由聊天

> 参考对象：MeChat（聊天式视觉小说）、Escape: Swipe, Date & Love（CMS 旧产品）
> 核心思路：**用固定剧情把人物立起来，再把人物交给 AI 去陪伴。**

---

## 1. 一句话定位

传统聊天小说的问题：内容是写死的，玩家消耗得比产出快，剧情读完就流失。
纯 AI 陪伴产品的问题：开局是一张空白的角色卡，玩家没有理由在乎这个角色。

本方案把两者接起来：

```
固定剧情（建立人物、共同经历、情感投入）
        ↓  完成第 N 章，关系达到门槛
AI 解锁（角色记得你们经历过的一切，可以自由聊）
        ↓  聊天积累好感 / 触发事件
新的固定章节（剧情高潮、重大转折仍由编剧掌控）
        ↺  循环
```

**固定剧情负责"让玩家在乎这个人"，AI 负责"让这个人一直在"。**

---

## 2. 核心循环

### 2.1 阶段一：固定剧情（Onboarding，建议 3–5 章）
- 形式沿用 MeChat：聊天界面、选项、表情回应、图片、语音。
- 目标不是讲完故事，而是完成三件事：
  1. **立人设**：性格、说话方式、秘密、伤口。
  2. **制造共同经历**：玩家做过的选择，后面 AI 要能提起。
  3. **埋钩子**：留一个没讲完的秘密 / 悬念，作为 AI 阶段的话题和后续章节的入口。
- 每个选项写入结构化"剧情状态"（见 §4.2），这是 AI 阶段的记忆来源。

### 2.2 阶段二：AI 解锁（关键时刻要做成剧情事件）

**解锁条件 = 完成第 N 章 AND 好感度 ≥ 阈值**（见 §8.3；根据 My Escape 历史数据，建议第 1 章末 AI 试聊、第 2 章末正式解锁，见 §9）。

- 解锁不要是一个弹窗，而是一个**剧情节点**，例如：
  - "他把私人号码给了你"
  - "她说：以后不用等我找你了，你想说什么都可以"
- 解锁后的**第一条 AI 消息建议半脚本化**（模板 + AI 填充），避免从精修剧本到 AI 的"质量断崖"。

### 2.3 阶段三：自由聊天 + 剧情回流
AI 聊天不能是漫无目的的闲聊，否则 1–2 周后同样会流失。需要几种"推力"：

| 机制 | 说明 |
|---|---|
| 主动消息 | 角色按作息、剧情状态主动找玩家（早安、出事了、想你了） |
| 秘密解锁 | 聊天累计好感 → 解锁角色隐藏秘密（沿用 MeChat 的 UNVEIL 卖点） |
| 剧情事件触发 | AI 聊天中检测到条件（好感、话题、时间）→ 推出下一段**固定章节** |
| 赛季更新 | 定期上线新章节，剧情大转折仍由编剧控制，AI 负责章节之间的日常 |

原则：**编剧掌控"大事"，AI 掌控"日常"。** 剧情走向的主干不交给 AI，避免角色崩坏和世界观失控。

## 3. 与 Escape 的区别（吸取的教训）

Escape 把"滑卡交友"和"扮演别人的视觉小说"塞进一个产品，两套代入逻辑互相打架。本方案保持**单一心智**：

- 玩家始终是"自己"，从剧情到 AI 聊天视角不切换。
- 剧情和聊天是同一段关系的前后两段，不是两个并列玩法。
- 先少而深：MVP 只做 1–3 个角色，把单个角色的体验做透，再扩角色库。

## 4. 技术方案

### 4.1 Prompt 分层
每次 AI 回复时，按以下层次组装上下文：

1. **世界观设定**（固定，可缓存）
2. **角色圣经 Character Bible**（固定，可缓存）：性格、说话风格样例、背景、禁区、不可改变的事实（canon）
3. **关系状态**（结构化）：好感度、关系阶段、已解锁秘密、当前剧情进度
4. **剧情记忆**：固定章节里玩家做过的关键选择（"第 2 章你替她挡了酒"）
5. **长期记忆**：聊天中提炼的事实（玩家名字、工作、喜好、说过的重要的事）
6. **近期对话**：最近 N 轮原文
7. **本轮指令**：是否要推动事件、是否要引导到下一章等

层 1–2 稳定不变，适合 prompt caching，能明显降低单条消息成本。

### 4.2 剧情状态 → AI 记忆
固定章节每个选项都要打标签，写入结构化存储，例如：

```json
{
  "character": "ethan",
  "chapter_done": 4,
  "affinity": 62,
  "choices": [
    {"ch": 2, "id": "defend_at_bar", "summary": "玩家在酒吧替 Ethan 解围"},
    {"ch": 3, "id": "kept_secret", "summary": "玩家答应不把他哥哥的事告诉任何人"}
  ],
  "secrets_unlocked": ["brother_accident"],
  "open_hooks": ["他父亲为什么突然回国"]
}
```

AI 能自然地说出"你上次在酒吧那样护着我，我其实记到现在"，**这就是这个产品和普通 AI 陪伴产品拉开差距的地方。**

### 4.3 记忆系统
- 短期：最近对话窗口。
- 长期：定期把对话总结成事实条目，用向量检索 + 结构化字段两种方式取。
- 玩家可见的"他记得的事"页面：增强"被记住"的感受，也方便玩家纠错。

### 4.4 多模态
| 能力 | 方案要点 |
|---|---|
| 语音 | 每个角色一个固定音色（TTS / 声音克隆，需获得配音演员授权） |
| 图片 | 角色形象一致性是难点：用角色参考图 / 专属微调模型 + 预制场景图库结合；建议 MVP 先用预制图库 + AI 选图，而非实时生成 |
| 表情回应 | 沿用 MeChat，AI 可以对玩家消息回表情，成本低、亲密感高 |

### 4.5 安全与审核层
- 输入 / 输出双向内容审核。
- 角色"出戏"检测：AI 承认自己是模型、违背角色设定 → 拦截重写。
- 危机识别：自伤 / 自杀等表述 → 跳出角色，提供求助资源。

## 5. 商业化

AI 聊天每条消息都有成本，商业模式必须覆盖推理成本：

| 付费点 | 说明 |
|---|---|
| 每日免费消息额度 / 体力 | 基础聊天免费有限，超出付费或订阅 |
| 订阅（推荐主力） | 无限或高额度聊天、更长记忆、优先回复 |
| 语音消息 | 角色语音回复按条付费或订阅权益 |
| 专属图片 | 好感门槛 + 付费解锁 |
| 剧情章节 / 关键选项 | 沿用传统互动小说付费方式（钻石选项） |
| 秘密解锁加速 | 付费跳过好感门槛 |

建议：固定剧情阶段保留传统的钻石选项付费，AI 阶段以订阅为主。

成本控制：模型分级（日常闲聊用小模型，关键事件 / 长回复用大模型）、prompt caching、回复长度控制。

## 6. 合规风险（上线前需法务确认）

- **AI 身份披露**：多地法规要求明确告知用户在与 AI 对话（如欧盟 AI 法案透明度义务；美国加州等地针对"陪伴型聊天机器人"的专门法规，涉及 AI 身份提示、未成年人保护、自伤应对流程等）。
- **未成年人**：年龄分级、年龄验证，恋爱 / 成人内容严格限制。
- **应用商店政策**：Apple / Google 对 AI 生成内容、用户生成内容、成人内容有专门审核要求。
- **情感依赖**：设计防沉迷提示，不用"不聊天我会难过"之类操纵性话术诱导付费。
- **声音 / 形象授权**：配音演员声音克隆、角色形象需要明确授权。
- **数据隐私**：聊天内容属于敏感数据，需要明确的存储、删除、是否用于训练的政策。

## 7. MVP 建议

**范围**
- 3 个角色 × 3 个题材（建议：黑帮/豪门、超自然、校园），每个角色 3–4 章固定剧情 + AI 解锁。同时验证不同题材下 AI 聊天的留存差异。
- 文字 + 表情 + 预制图片 + 少量语音；暂不做实时生图。
- 剧情状态记忆 + 基础长期记忆。
- 1 个剧情回流事件（聊天好感达标 → 解锁第 5 章）。

**核心指标**

| 漏斗 | 指标 |
|---|---|
| 剧情阶段 | 第 1 章完成率、到达解锁章节的比例 |
| 解锁时刻 | 解锁后 24 小时内发出第一条消息的比例 |
| AI 阶段 | 人均每日消息数、D1 / D7 / D30 留存（对比纯剧情用户） |
| 质量 | 出戏率、玩家差评 / 举报率、"他记得"类正反馈 |
| 商业 | 付费转化率、ARPPU、**单用户 AI 成本 / 单用户收入** |

**要验证的假设**
1. 固定剧情铺垫过的 AI 角色，留存是否显著高于直接开聊的 AI 角色（可做 A/B：有剧情 vs 无剧情）。
2. 玩家愿不愿意为 AI 聊天付订阅费，能不能覆盖推理成本。
3. 剧情回流机制能否防止 AI 阶段的后期流失。

## 8. 已确认决策及影响

| 项目 | 决策 |
|---|---|
| 目标市场 | 北美 |
| 品类 | 恋爱为主，多题材 |
| 内容尺度 | 17+ |
| 解锁方式 | 章节进度 + 好感度叠加 |
| 资产复用 | 不复用，全新 IP / 角色 / 美术 |

### 8.1 北美 · 恋爱 · 多题材

**题材 = 世界观模板。** 每个题材做一份可复用的世界观设定 + 角色原型库，新角色在模板上生产：

| 题材 | 典型原型 | AI 聊天的语气要点 |
|---|---|---|
| 黑帮 / 豪门 | 黑手党继承人、冷面 CEO | 占有欲、保护欲，危险感但不越线 |
| 超自然 | 狼人 Alpha、吸血鬼 | 宿命感、秘密身份，世界观规则要严格守住 |
| 校园 / 青春 | 校草、宿敌、竞争对手 | 轻松、斗嘴、Enemies to Lovers |
| 悬疑 / 惊悚 | 侦探、可疑的邻居 | 信息差、试探，悬念钩子密集 |
| 科幻 / 奇幻 | 星际军官、精灵王子 | 世界观术语多，对角色圣经一致性要求最高 |

- 题材之间是**角色库的扩展**，不是玩法切换；玩家视角始终是"自己"（避免 Escape 的心智拆散问题）。
- 角色语言：美式英语、北美流行的恋爱套路（slow burn、enemies to lovers、fake dating、forbidden love 等）。剧本需母语编剧精修，AI 回复风格也要用母语样例调校。
- 主力用户预估为北美女性向，时区与作息影响"主动消息"的推送时间。

### 8.2 内容尺度 17+

**允许：** 浪漫与暗示性内容、亲吻和亲密氛围（"fade to black" 式处理）、成熟主题（危险关系、暴力冲突的叙述、酒精）、适度粗口。
**不允许：** 露骨性描写、色情图片、未成年角色的任何浪漫内容、美化自伤 / 违法行为、真实人物。

落地要求：

1. **商店分级**：Google Play 走 IARC 问卷（对应 ESRB Mature 17+）。Apple 已改为 4+/9+/13+/16+/18+ 的新分级体系，不再有 17+，需按新问卷评估落到 16+ 还是 18+，**由法务 / 发行确认**。另外两家商店对 AI 生成内容和用户自由输入都有额外问卷和审核要求。
2. **年龄门槛**：注册年龄确认，配合商店 / 系统级年龄信号（北美多个州已有应用年龄验证相关立法，需持续跟踪）。
3. **AI 尺度控制**（AI 阶段是风险最高的部分，固定剧情可人工把关，AI 回复不行）：
   - 角色圣经里写明亲密内容的边界和"转场"写法（AI 在越线前主动收住、转为暗示）。
   - 输出审核分级：轻度暗示放行；接近露骨 → 重写；露骨 / 违规 → 拦截。
   - 玩家试图诱导越线时，角色以"人设内"方式拒绝（例如害羞、转移话题），而不是生硬的系统提示，减少出戏。
   - 角色设定年龄全部 18+，并在角色圣经中写死。
4. **模型选择**：17+ 尺度在主流商用模型的使用政策内，可直接用主流 API；需确认所选供应商对恋爱陪伴类应用的具体条款。
5. **陪伴类法规**：AI 身份披露、自伤危机应对流程、对疑似未成年用户的保护措施，按北美各州（如加州的陪伴型聊天机器人法规）落实。

### 8.3 解锁：章节 + 好感度叠加

```
解锁 AI = 完成第 N 章（建议 N=2，第 1 章末先给 AI 试聊，理由见 §9.2）  AND  好感度 ≥ 阈值
```

- **好感来源**：剧情选项（主要）、表情回应、支线小剧情、付费选项。
- **防卡关**：章节完成但好感不足的玩家是流失高危人群，必须有路径补足：
  - 补好感的**支线短剧情**（免费，每日 1 段）
  - 付费的"关键选项"直接加大量好感
  - 好感差距可见（进度条 + 角色暗示："我还不确定能不能完全信任你……"）
- **阈值设计**：免费玩家正常选择应能在第 N 章或 N+1 章达到，不要把解锁做成硬付费墙；AI 聊天本身才是长期付费点。
- **解锁后好感继续生效**：解锁秘密、专属图片 / 语音、下一段固定章节都用好感门槛，形成持续目标。
- 好感过低时可以有"关系危机"剧情，作为回流事件而不是惩罚。

### 8.4 全新 IP，不复用资产

- **冷启动成本主要在角色生产**：每个角色需要角色圣经、3–5 章剧本、立绘 + 场景图库、声音。建议搭一条**AI 辅助生产管线**：
  1. AI 生成角色概念与圣经初稿 → 编剧精修
  2. AI 生成章节剧本初稿 → 母语编剧精修（固定剧情质量是第一印象，不能省）
  3. 美术：先定角色主视觉，再基于参考图批量生产场景图，人工筛选
  4. 声音：签约配音演员并取得声音克隆授权
- **全新 IP 注意事项**：形象、名字、声音避免与现有作品或真人雷同；AI 生成美术需确认版权与商店政策要求。
- 目标：把单角色从立项到上线的周期压到可持续周更的节奏（每周一个新角色或新章节）。

## 9. My Escape 历史复盘与启示

> 数据来源：My Escape 内容复盘 PPT、产品现状总结页、Facebook 买量回收表（英语区 / T1：US、UK、CA、AU）。

### 9.1 关键数据

**章节漏斗（各故事区间）**

| 指标 | 数值 |
|---|---|
| 第 1 章留存 | 45% – 75% |
| 第 5 章留存 | 3.66% – 16% |
| 章内流失 | 第 1 章 0.19%–3% → 第 3 章 1.5%–16.7% → 第 4 章 2.82%–18.96% → **第 5 章 26.73%–55%** |
| 最佳开篇 | Isaac Todd 第 1 章 74%（开局直接、攻势强） |
| 典型 | Cameron Charles 第 1 章 55% → 第 5 章 15% |

（PPT 中成对数字按"最好–最差故事"区间理解，需与原作者确认。）

**买量回收（Facebook，英语区）**

| 素材 / 时段 | CPI | D0 ROAS | D20 ROAS | D20 / D0 增长倍率 |
|---|---|---|---|---|
| Escape 自有素材 0318–0331 | $8.56 | 17.2% | 64.3% | 3.74x |
| My Fantasy 3D 素材 0407–0428 | $5.86 | 20.6% | 61.4% | 2.98x |
| 全量 0401–0415 | $7.02 | 17.3% | 63.9% | 3.69x |
| 全量 0416–0430 | $4.31 | 17.0% | 61.9% | 3.64x |

- 用 0416–0430 拟合：**1 年 LTV 倍率约 6.0x**；按 CPI $4.31、首日 LTV $0.73、平台分成 30% 计算，要 1 年回收 143% 需要 **8.4x**。缺口约 40%。
- 3D 素材 CPI 更低、首日更好，但从第 2–3 天开始增长倍率落后：**素材承诺与产品体验不一致，买来的用户留不住。**

**产品层结论（原团队）**：iChat（Match & Date）模式的商业模型已验证，但**留存和内容储备量撑不起长线 LTV**。

### 9.2 对新方案的启示

1. **AI 正好补的是 My Escape 的短板。** 原问题是"内容消耗快、产出慢，长线 LTV 不够"，AI 自由聊天就是无限内容供给。新方案的商业目标可以直接量化为：**把 1 年 LTV 倍率从 ~6x 拉到 ≥ 8.4x**（同时扣除 AI 推理成本）。核心观察指标是 D3 之后的 ROAS 增长曲线，而不是 D0。
2. **解锁不能放在第 3 章以后。** 第 5 章只剩 4%–16% 的用户，第 3 章后流失明显加速。如果 AI 在第 3 章 + 好感门槛后才解锁，大部分用户根本走不到。调整为：
   - 第 1 章末：**AI 试聊**（少量免费消息，角色主动发来一条"私信"），让用户第一时间尝到 AI 的不同；
   - 第 2 章末 + 好感达标：正式解锁；
   - 第 3 章以后的固定章节改为"剧情事件"，穿插在 AI 聊天之间，而不是一条长线漏斗。
3. **用户来是为了约会回报，不是为了剧情。** 原团队的结论是"这是约会游戏，不是约会故事游戏"，冗余对白会直接导致流失。新方案在 17+ 尺度内的对应做法：
   - 固定章节要短、快、目的明确：每章约 70 行，结构沿用 **30 行聊天（世界观 + LI 自我介绍 + 明确约会目标 + 第 1 张 CG）→ 40 行约会（关系升级 + 反转）**，每章结尾留钩子（新信息 / 反转 / 暧昧时刻）。
   - 开篇第一句就给出明确目的（"今晚陪我喝一杯？""帮我搞砸我朋友的婚礼"），信息量要大。
   - **AI 聊天同样要有目的感**：每次对话都在朝"见面 / 约会 / 关系升级"推进，避免变成无目的闲聊。
4. **LI 按"约会目的 + 热度节奏"分类，而不只是按职业。** 原方案的分类（闪婚 / 友情 / 一夜情 / 激情；极速 / 快速 / 正常 / 慢热）可直接迁移，在 17+ 下改为"亲密推进速度"：
   - 角色圣经增加 `heat_pace` 字段，决定 AI 阶段的暧昧推进速度和转场时机；
   - 不同节奏的角色覆盖不同用户口味，也可以做 A/B 看哪类留存 / 付费最好。
   - 注意：17+ 不能做露骨内容，"热度"体现在张力、暗示和 fade-to-black 转场上。原 PPT 的部分方向超出 17+，不能照搬。
5. **LI 要有"灵魂"：有弱点、有阴暗面、有反差。** CG 卡只服务一个目的——立人设，聚焦 LI 和关键瞬间，要有反差（如 Thompson Gruns：霸总 + 和孩子在一起的温柔一面）。在 AI 阶段，这些弱点和反差写进角色圣经，作为 AI 主动展开话题和"秘密解锁"的素材。
6. **买量素材必须和产品体验一致。** My Fantasy 3D 素材的教训说明，低 CPI 的素材如果和实际体验不符，会拉低长线回收。新产品素材应直接展示"角色记得你、主动找你"的 AI 聊天体验，并用增长倍率而不是 CPI / D0 来评估素材。

### 9.3 MVP 对标基线

| 指标 | My Escape 基线 | 新方案目标 |
|---|---|---|
| 第 1 章留存 | 45%–75% | ≥ 70%（全部按最佳开篇标准写） |
| 进入 AI 阶段的用户比例 | — | ≥ 40% 安装用户 |
| D20 / D0 ROAS 倍率 | ~3.7x | ≥ 4.5x |
| 1 年 LTV 倍率（拟合） | ~6.0x | ≥ 8.4x（扣除 AI 成本后） |
