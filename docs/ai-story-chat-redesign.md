# AI 重构方案：剧情引入 + AI 自由聊天

> 参考对象：MeChat（聊天式视觉小说）、Escape: Swipe, Date & Love（CMS 旧产品）
> 核心思路：**用固定剧情把人物立起来，再把人物交给 AI 去陪伴。**

---

## 1. 一句话定位

传统聊天小说的问题：内容是写死的，玩家消耗得比产出快，剧情读完就流失。
纯 AI 陪伴产品的问题：开局是一张空白的角色卡，玩家没有理由在乎这个角色。

本方案把两者接起来：

```
固定剧情（建立人物、共同经历、情感投入）
        ↓  完成第 N 章，关系达到门槛
AI 解锁（角色记得你们经历过的一切，可以自由聊）
        ↓  聊天积累好感 / 触发事件
新的固定章节（剧情高潮、重大转折仍由编剧掌控）
        ↺  循环
```

**固定剧情负责"让玩家在乎这个人"，AI 负责"让这个人一直在"。**

---

## 2. 核心循环

### 2.1 阶段一：固定剧情（Onboarding，建议 3–5 章）
- 形式沿用 MeChat：聊天界面、选项、表情回应、图片、语音。
- 目标不是讲完故事，而是完成三件事：
  1. **立人设**：性格、说话方式、秘密、伤口。
  2. **制造共同经历**：玩家做过的选择，后面 AI 要能提起。
  3. **埋钩子**：留一个没讲完的秘密 / 悬念，作为 AI 阶段的话题和后续章节的入口。
- 每个选项写入结构化"剧情状态"（见 §4.2），这是 AI 阶段的记忆来源。

### 2.2 阶段二：AI 解锁（关键时刻要做成剧情事件）
- 解锁不要是一个弹窗，而是一个**剧情节点**，例如：
  - "他把私人号码给了你"
  - "她说：以后不用等我找你了，你想说什么都可以"
- 解锁后的**第一条 AI 消息建议半脚本化**（模板 + AI 填充），避免从精修剧本到 AI 的"质量断崖"。

### 2.3 阶段三：自由聊天 + 剧情回流
AI 聊天不能是漫无目的的闲聊，否则 1–2 周后同样会流失。需要几种"推力"：

| 机制 | 说明 |
|---|---|
| 主动消息 | 角色按作息、剧情状态主动找玩家（早安、出事了、想你了） |
| 秘密解锁 | 聊天累计好感 → 解锁角色隐藏秘密（沿用 MeChat 的 UNVEIL 卖点） |
| 剧情事件触发 | AI 聊天中检测到条件（好感、话题、时间）→ 推出下一段**固定章节** |
| 赛季更新 | 定期上线新章节，剧情大转折仍由编剧控制，AI 负责章节之间的日常 |

原则：**编剧掌控"大事"，AI 掌控"日常"。** 剧情走向的主干不交给 AI，避免角色崩坏和世界观失控。

## 3. 与 Escape 的区别（吸取的教训）

Escape 把"滑卡交友"和"扮演别人的视觉小说"塞进一个产品，两套代入逻辑互相打架。本方案保持**单一心智**：

- 玩家始终是"自己"，从剧情到 AI 聊天视角不切换。
- 剧情和聊天是同一段关系的前后两段，不是两个并列玩法。
- 先少而深：MVP 只做 1–3 个角色，把单个角色的体验做透，再扩角色库。

## 4. 技术方案

### 4.1 Prompt 分层
每次 AI 回复时，按以下层次组装上下文：

1. **世界观设定**（固定，可缓存）
2. **角色圣经 Character Bible**（固定，可缓存）：性格、说话风格样例、背景、禁区、不可改变的事实（canon）
3. **关系状态**（结构化）：好感度、关系阶段、已解锁秘密、当前剧情进度
4. **剧情记忆**：固定章节里玩家做过的关键选择（"第 2 章你替她挡了酒"）
5. **长期记忆**：聊天中提炼的事实（玩家名字、工作、喜好、说过的重要的事）
6. **近期对话**：最近 N 轮原文
7. **本轮指令**：是否要推动事件、是否要引导到下一章等

层 1–2 稳定不变，适合 prompt caching，能明显降低单条消息成本。

### 4.2 剧情状态 → AI 记忆
固定章节每个选项都要打标签，写入结构化存储，例如：

```json
{
  "character": "ethan",
  "chapter_done": 4,
  "affinity": 62,
  "choices": [
    {"ch": 2, "id": "defend_at_bar", "summary": "玩家在酒吧替 Ethan 解围"},
    {"ch": 3, "id": "kept_secret", "summary": "玩家答应不把他哥哥的事告诉任何人"}
  ],
  "secrets_unlocked": ["brother_accident"],
  "open_hooks": ["他父亲为什么突然回国"]
}
```

AI 能自然地说出"你上次在酒吧那样护着我，我其实记到现在"，**这就是这个产品和普通 AI 陪伴产品拉开差距的地方。**

### 4.3 记忆系统
- 短期：最近对话窗口。
- 长期：定期把对话总结成事实条目，用向量检索 + 结构化字段两种方式取。
- 玩家可见的"他记得的事"页面：增强"被记住"的感受，也方便玩家纠错。

### 4.4 多模态
| 能力 | 方案要点 |
|---|---|
| 语音 | 每个角色一个固定音色（TTS / 声音克隆，需获得配音演员授权） |
| 图片 | 角色形象一致性是难点：用角色参考图 / 专属微调模型 + 预制场景图库结合；建议 MVP 先用预制图库 + AI 选图，而非实时生成 |
| 表情回应 | 沿用 MeChat，AI 可以对玩家消息回表情，成本低、亲密感高 |

### 4.5 安全与审核层
- 输入 / 输出双向内容审核。
- 角色"出戏"检测：AI 承认自己是模型、违背角色设定 → 拦截重写。
- 危机识别：自伤 / 自杀等表述 → 跳出角色，提供求助资源。

## 5. 商业化

AI 聊天每条消息都有成本，商业模式必须覆盖推理成本：

| 付费点 | 说明 |
|---|---|
| 每日免费消息额度 / 体力 | 基础聊天免费有限，超出付费或订阅 |
| 订阅（推荐主力） | 无限或高额度聊天、更长记忆、优先回复 |
| 语音消息 | 角色语音回复按条付费或订阅权益 |
| 专属图片 | 好感门槛 + 付费解锁 |
| 剧情章节 / 关键选项 | 沿用传统互动小说付费方式（钻石选项） |
| 秘密解锁加速 | 付费跳过好感门槛 |

建议：固定剧情阶段保留传统的钻石选项付费，AI 阶段以订阅为主。

成本控制：模型分级（日常闲聊用小模型，关键事件 / 长回复用大模型）、prompt caching、回复长度控制。

## 6. 合规风险（上线前需法务确认）

- **AI 身份披露**：多地法规要求明确告知用户在与 AI 对话（如欧盟 AI 法案透明度义务；美国加州等地针对"陪伴型聊天机器人"的专门法规，涉及 AI 身份提示、未成年人保护、自伤应对流程等）。
- **未成年人**：年龄分级、年龄验证，恋爱 / 成人内容严格限制。
- **应用商店政策**：Apple / Google 对 AI 生成内容、用户生成内容、成人内容有专门审核要求。
- **情感依赖**：设计防沉迷提示，不用"不聊天我会难过"之类操纵性话术诱导付费。
- **声音 / 形象授权**：配音演员声音克隆、角色形象需要明确授权。
- **数据隐私**：聊天内容属于敏感数据，需要明确的存储、删除、是否用于训练的政策。

## 7. MVP 建议

**范围**
- 1–2 个角色，每个角色 3–4 章固定剧情 + AI 解锁。
- 文字 + 表情 + 预制图片 + 少量语音；暂不做实时生图。
- 剧情状态记忆 + 基础长期记忆。
- 1 个剧情回流事件（聊天好感达标 → 解锁第 5 章）。

**核心指标**

| 漏斗 | 指标 |
|---|---|
| 剧情阶段 | 第 1 章完成率、到达解锁章节的比例 |
| 解锁时刻 | 解锁后 24 小时内发出第一条消息的比例 |
| AI 阶段 | 人均每日消息数、D1 / D7 / D30 留存（对比纯剧情用户） |
| 质量 | 出戏率、玩家差评 / 举报率、"他记得"类正反馈 |
| 商业 | 付费转化率、ARPPU、**单用户 AI 成本 / 单用户收入** |

**要验证的假设**
1. 固定剧情铺垫过的 AI 角色，留存是否显著高于直接开聊的 AI 角色（可做 A/B：有剧情 vs 无剧情）。
2. 玩家愿不愿意为 AI 聊天付订阅费，能不能覆盖推理成本。
3. 剧情回流机制能否防止 AI 阶段的后期流失。

---

## 8. 待决策问题

1. 目标市场与题材：北美女性向恋爱为主？还是多题材？
2. 内容尺度：分级到哪一档，直接决定模型选择、审核策略和商店分级。
3. 解锁门槛：固定第 N 章，还是叠加好感度？
4. 角色数量策略：少而深，还是快速铺量（可用 AI 辅助生产剧本，但需人工精修）？
5. 是否复用 CMS 现有 IP / 角色 / 美术资产（如 Escape 的角色库）冷启动。
