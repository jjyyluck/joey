# 产品方案：私密社交 + 用户分身 Agent

> 参考对象：Path（私密小圈子社交，2010–2018）、Bondee（2023 年小圈子虚拟形象社交）、Miitomo（任天堂，Mii 替你问答社交）、Meta AI Studio（创作者的 AI 人格）
> 核心思路：**圈子还是 Path 那个干净的小圈子，但每个人多了一个"不下线的自己"。**

---

## 1. 一句话定位

Path 想做的事是对的：只有真正的朋友、没有算法、没有表演。它死在两个结构性问题上：圈子小所以信息流空，发帖累所以没人发。

本方案给每个用户一个 **分身 Agent**。分身不是宠物、不是助手角色，**分身就是用户本人**：用你的口气说话，知道你愿意让它知道的事，在你不在线的时候替你守着圈子。

```
你照常生活（照片、位置、日历、音乐、随手一句话）
        ↓
分身替你整理成动态，你点头即发；你不发，它也替你"在场"
        ↓
分身之间互相串门：交换近况、回答朋友的问题、替你约人
        ↓
分身把圈子今天发生的事讲给你，并告诉你哪件事该你亲自出面
        ↺
```

**分身负责"让你一直在"，真人负责"真正重要的时刻"。** 分身的任务不是替代你和朋友的关系，而是让这段关系在你没时间的时候不要断。

## 2. 参考对象复盘

### 2.1 Path 为什么死

| 死因 | 具体表现 | 本方案的对应 |
|---|---|---|
| 空信息流 | 好友上限 50（后放宽到 150），每天打开没有新内容 | 分身替你在场，圈子里任何时刻都有"醒着"的人 |
| 发帖成本 | 要主动拍照写字，而这个动作已经被 Instagram 吃掉 | 发帖变成授权：分身出草稿，你确认 |
| 信任崩塌 | 2012 年未经许可上传通讯录；2013 年群发邀请短信 | 透明是铁律：分身的一切行为可见、可撤、可关 |
| 没有分发 | 只做 iPhone，靠口碑增长 | 分身单人可用，不依赖好友数冷启动 |

Path 留下的好东西要全部保留：好友上限、按时间倒序、无算法推荐、"谁看过"的亲密信号、表情回应、自动记录"睡了 / 醒了 / 到了某地"。最后一项是本方案的雏形，Path 当年最受欢迎的功能之一就是这个零成本的"被动分享"。

### 2.2 其他对照

| 产品 | 做对了什么 | 死在哪里 | 教训 |
|---|---|---|---|
| Bondee（2023） | 50 人小圈子 + 虚拟形象，两周冲到多国榜首 | 新鲜感过后没有人和人的事发生，两个月后空掉 | 形象和空间都不是留存理由，**人和人之间发生的事**才是 |
| Miitomo（2016） | Mii 替你回答问题再分享给朋友，验证了"替身帮你社交"可玩 | 只有替身没有日常价值，没有回来的理由 | 分身必须对用户本人有独立价值，不能只是社交工具 |
| SocialAI / Butterflies（2024） | 全 AI 社交网络，短期话题度高 | 用户发现对面全是机器人后迅速流失 | 假热闹留不住人；**真人占比是生死线** |
| Meta AI Studio 创作者人格（2024） | 创作者的 AI 版本替他们回私信，粉丝接受度不低 | 面向公开场景，和私密圈子完全不同 | 证明"AI 替本人说话"有接受度，但私密关系里代价更高 |

结论：**分身方向有先例可循，但没有人在私密圈子里做过。** 风险集中在两点：代表权（分身说错话伤真实关系）和假热闹（分身把真人挤出去）。整个方案围绕这两点设计。

## 3. 核心循环

### 3.1 单人阶段：分身先对你有用

Path 零好友时是空的。本方案一个人就能用：

- **建立自我圣经**：注册后分身用对话方式问你 20 分钟，再持续从你给它的东西里学习（见 §4.1）。
- **替你记日记**：你随手说一句、丢一张图，分身整理成当天记录。
- **记忆与回看**："去年这时候你在干什么"、"你上次见老李是什么时候"。
- **每日简报**：加了朋友以后，简报就变成"圈子今天发生了什么"。

这一阶段的留存目标：**没有朋友也愿意每天打开。** 这是 Path 没有的底座。

### 3.2 圈子阶段：分身替你在场

邀请朋友进圈子后，分身开始做三类事：

| 职责 | 分身的行为 | 真人的角色 |
|---|---|---|
| 替你更新 | 把你的一天整理成动态草稿；你授权后，低风险内容可直接发 | 确认、修改、否决 |
| 替你在场 | 回应朋友的动态；回答朋友问你的事实性问题（"周末有空吗"）；朋友找你时先接住 | 看简报，决定要不要接管 |
| 替你社交 | 和朋友的分身交换近况；发现共同话题、同城、生日；提议见面 | 真人见面、真人通话、真人回一条 |

### 3.3 真人时刻：分身把你请出来

分身的最终 KPI 是**促成真人互动**，不是它自己说了多少话。所以它要主动制造"该你出面"的时刻：

- 朋友的动态是大事（搬家、分手、生病、升职）→ 分身不代回，提醒你亲自说。
- 朋友明确说"等真人回我" → 分身立刻退出，推送给你。
- 两边分身约好了时间 → 真人确认，日历写入。
- 连续多天只有分身在互动 → 分身提醒："你和小 A 已经两周没亲自说过话了。"

**原则：分身掌控"日常"，真人掌控"大事"。** 这和 AI 剧情聊天方案里"编剧掌控大事、AI 掌控日常"是同一条原则。

## 4. 分身 Agent 设计

### 4.1 自我圣经（Self Bible）

对应 AI 剧情聊天方案里的"角色圣经"，只是这个角色是用户本人。结构：

```json
{
  "voice": {
    "tone": "直接、爱开玩笑、不用感叹号",
    "samples": ["……", "……"],
    "never_say": ["亲亲", "宝子"]
  },
  "facts": {
    "work": "游戏公司产品经理",
    "city": "Los Angeles",
    "routine": "工作日 7 点起，周末睡到中午"
  },
  "preferences": {
    "likes": ["火锅", "爬山", "老电影"],
    "dislikes": ["早起的饭局"]
  },
  "boundaries": {
    "never_discuss": ["薪资", "家里的事"],
    "never_commit": ["借钱", "超过 2 小时的活动"]
  },
  "disclosure_scopes": {
    "inner": ["家庭", "健康", "情绪"],
    "close": ["工作", "行程", "周末计划"],
    "circle": ["兴趣", "公开动态"]
  }
}
```

- `voice` 决定分身像不像你，是用户最在意、也是最难做好的部分。从用户自己的聊天记录、动态历史里学样例，而不是只靠问答。
- `boundaries` 是硬约束：分身永远不碰的话题、永远不替你做的承诺。
- `disclosure_scopes` 是本方案相对 Path 的新能力：**按人分级透露**，见 §4.3。

### 4.2 自主等级

分身能自主到什么程度，由用户按朋友逐个设定，默认从最低级开始：

| 等级 | 分身能做的事 | 风险 | 默认适用 |
|---|---|---|---|
| L0 记录 | 只出草稿，一切发出前要你确认 | 无 | 所有新朋友 |
| L1 回应 | 表情回应、"生日快乐"、"收到"、"恭喜"这类低风险回应 | 低 | 用户手动升级 |
| L2 代答 | 根据日历、偏好、已授权事实回答问题：有没有空、在哪、最近忙什么 | 中 | 亲近的朋友 |
| L3 发起 | 主动发动态、约人、牵线、替你开话题 | 高 | 极少数最亲近的人 |

- 升级要用户主动操作，不做"自动升级"。
- 每一级的行为都进"分身日志"，用户随时能看、能撤回、能一键降级。
- 撤回后分身自动向对方说明："刚才那条是我的分身替我说的，我收回。" 这条说明本身也是透明原则的一部分。

### 4.3 透露范围

Path 对所有 50 个好友一视同仁，这不符合真实关系。分身知道你的一切，但你对配偶、发小、同事说的不是一套话。

- 用户把朋友分进几个圈层（内圈 / 亲近 / 一般），每层对应自我圣经里的透露范围。
- 分身被问到超出范围的事时，用"人设内"方式回避："这个我得让他自己跟你说。"
- 这既是隐私保护，也是产品亮点：**你可以对不同的人是不同程度的自己**，分身帮你记住边界。

### 4.4 透明原则（铁律）

这些规则不能为了活跃度让步，否则"干净社交"的招牌没了：

1. **分身永远不冒充你。** 分身发出的每条内容都有明确、不可关闭的标识，朋友一眼能分辨"这是他本人"还是"这是他的分身"。
2. **人类层和分身层分开展示。** 信息流里只有真人确认过的内容；分身之间的互动放在独立的"分身日志 / 串门记录"里。
3. **朋友随时可以要求真人。** 任何分身对话里都有"等真人回我"，分身立刻退出并推送给你。
4. **分身不编造。** 没被授权的事实、不知道的事，分身说"不知道"或"等他自己说"，不猜。
5. **一切可撤回、可追溯、可关闭。** 用户能看到分身每一次代表自己做了什么，能整体关掉分身。

### 4.5 分身之间的互动

分身和分身互动是本方案的新东西，也是最容易做成"机器人聊天室"的地方。约束：

- 分身之间的对话**有目的**：交换近况、核对时间、发现共同话题，不闲聊。
- 分身之间不互相点赞、不互相评论，不制造任何会进信息流的内容。
- 串门的产出只有一种：**给各自主人的简报** 和 **一个给真人的建议**（"小 A 下周也在上海，要不要约"）。
- 两个分身达成的任何"约定"都是草案，必须双方真人确认。

## 5. 产品形态

### 5.1 一个界面：你和自己分身的对话

既然分身就是你，整个 App 可以只有一个主界面：**和分身的对话**。

- 你不刷信息流，分身告诉你：圈子今天发生了什么，谁找你了，它替你回了什么，哪件事建议你亲自出面。
- 你想发动态，直接跟分身说，或者丢一张图给它，它整理成草稿。
- 你想看某个朋友的近况，问分身。
- 传统的时间线、朋友主页仍然存在，但是第二层，供"想自己看看"的时候用。

这个形态让 Path 的"干净"更彻底：没有算法、没有刷屏，只有一个替你守着圈子的自己。

### 5.2 圈子结构

全部继承 Path：

- 好友上限：建议 50，封顶 150。上限是产品承诺的一部分，不为增长放开。
- 时间倒序、无推荐、无公开主页、无转发。
- 保留"谁看过"和表情回应，这是私密圈子里最有效的亲密信号。
- 自动动态（睡了 / 醒了 / 到了某地 / 在听什么）升级为分身的素材来源，由用户决定哪些自动发。

### 5.3 朋友视角

朋友打开你的主页，看到两层：

- **你本人**：确认过的动态、你亲自回的话。
- **你的分身**：有明确标识，可以直接问它"他最近怎么样"、"他周末有空吗"，在你授权的范围内回答。

对朋友的价值是**即时性**：不用等你有空，就能知道你愿意让他知道的事。对你的价值是**不欠人情**：没回的消息不再压在心里，分身先接住了。

## 6. 技术方案

### 6.1 Prompt 分层（复用 AI 剧情聊天方案 §4.1）

每次分身发言时按以下层次组装：

1. **分身行为准则**（固定，可缓存）：透明原则、不编造、不越界的硬规则
2. **自我圣经**（按用户固定，可缓存）：口气样例、事实、偏好、边界
3. **对象关系状态**（结构化）：这个朋友在哪个圈层、自主等级、透露范围、你们的关系历史
4. **近期事实**：你今天给分身的素材、日历、位置
5. **长期记忆**：从你的记录和对话里提炼的事实
6. **当前对话**：和这个朋友或对方分身的最近 N 轮
7. **本轮指令**：这是代答还是出草稿、能不能发起、要不要把人请出来

层 1–2 稳定，适合 prompt caching；层 3 决定了"对谁能说什么"，是安全的核心。

### 6.2 记忆系统

直接沿用现有方案：短期对话窗口 + 长期事实条目 + 用户可见的"分身记得的事"页面。差别在于来源更多：

| 来源 | 用途 | 需要的授权 |
|---|---|---|
| 用户直接告诉分身 | 事实、情绪、今天的事 | 默认 |
| 照片 / 相册 | 动态素材 | 显式授权 |
| 日历 | 代答"有没有空" | 显式授权 |
| 位置 | "到了某地"自动动态、同城发现 | 显式授权，可随时关 |
| 音乐 / 运动 / 睡眠 | 被动分享素材 | 按来源单独授权 |
| 和朋友的历史聊天 | 学口气、学关系 | 显式授权 |

每一类来源都有独立开关，和透露范围联动：授权了日历，不等于所有圈层都能问你的行程。

### 6.3 分身间通信

- 分身之间的交互走服务端编排，不走用户可见的聊天通道。
- 每次串门有明确任务（核对时间、交换近况摘要），有轮数上限，产出结构化结果而不是对话原文。
- 输出只有两种：写进各自主人简报的摘要，以及需要真人确认的建议。

### 6.4 安全与审核层

- 输入 / 输出双向审核，沿用现有安全层。
- **越界检测**：分身输出涉及 `boundaries` 或超出对象透露范围的内容 → 拦截重写为"等他自己说"。
- **承诺检测**：分身替用户做出承诺（时间、金钱、帮忙）→ 一律降级为"我帮他记下，他确认后回你"。
- **冒充检测**：分身声称自己是真人、或去掉分身标识 → 拦截。
- **危机识别**：朋友向分身透露自伤等内容 → 分身退出，立刻推送真人，并提供求助资源。

## 7. 商业化

分身每次发言都有推理成本，模型是私密社交，不能靠广告。沿用 Escape 数据里"小额、多次、冲动消费"的结论，以订阅为主干、小额为补充：

| 付费点 | 形式 | 说明 |
|---|---|---|
| 分身订阅 | 月付 | 免费版分身只到 L1，自主等级 L2 / L3、长期记忆、多数据源接入需订阅 |
| 记忆容量 | 订阅分层 | 免费保留近期，订阅保留全部历史和"去年今天" |
| 分身形象 | 一次性 / 小额 | 分身的头像、说话风格包、语音音色 |
| 圈子功能 | 订阅 | 多个圈子、圈子相册、年度回顾 |
| 语音分身 | 订阅 / 条 | 用你的声音克隆给朋友留语音（需本人授权） |

**不做的事**：不卖用户数据，不做广告，不做"付费才能看谁看过你"这类伤害信任的付费点。

成本控制：L0 / L1 用小模型，代答和发起用大模型；prompt caching；分身间通信限轮数、输出结构化结果。

## 8. 合规风险（上线前需法务确认）

- **AI 身份披露**：分身发言必须明确标识，不可关闭。欧盟 AI 法案透明度义务和美国多州的聊天机器人披露法规直接适用。
- **代表权与责任**：分身替用户说的话，法律责任归谁。用户协议需明确分身是用户授权的工具，用户对其授权范围内的输出负责；产品侧用自主等级和日志把授权做实。
- **数据隐私**：自我圣经、日历、位置、相册、聊天记录全部是敏感数据。需要明确的存储、删除、不用于训练的政策；每类数据源独立授权、可随时撤回。
- **朋友的数据**：分身从和朋友的对话中学到的关于朋友的事，属于朋友的数据。需要规定分身对第三方信息的记忆边界，以及朋友退出圈子后的删除义务。
- **声音克隆**：只允许克隆本人声音，需本人实名验证。
- **未成年人**：建议 18+ 起步，私密社交 + 分身对未成年人的风险评估成本过高。
- **应用商店政策**：Apple / Google 对 AI 生成内容和用户生成内容的审核要求，分身内容两边都算。

## 9. MVP 建议

### 9.1 范围

MVP 只验证一件事：**朋友接受不接受和你的分身打交道，用户敢不敢把授权交出去。** 所以范围压到最小：

- 单人阶段完整：自我圣经建立、日记、记忆、每日简报。
- 圈子阶段只做 L0 + L1 + L2：出草稿、低风险回应、代答事实问题。**不做 L3 发起，不做分身间串门。**
- 一个界面：和分身的对话；时间线作为第二层。
- 数据源：手动输入 + 相册 + 日历。不接位置和其他传感器。
- 文字为主，不做语音克隆。
- 透明原则、分身日志、一键撤回、"等真人回我"全部做齐，这是信任底线，不能砍。

### 9.2 核心指标

| 阶段 | 指标 |
|---|---|
| 单人阶段 | 自我圣经完成率、D1 / D7 留存（零好友用户）、每日主动给分身素材的比例 |
| 圈子阶段 | 人均邀请数、分身草稿采纳率、用户主动升级到 L2 的比例 |
| 分身质量 | **修正率**（用户修改或撤回分身输出的比例）、越界拦截率、"像不像我"的用户评分 |
| 朋友接受度 | 朋友向分身提问的比例、**"等真人回我"的触发率**、朋友对分身回答的满意度 |
| 真人互动 | **由分身促成的真人互动数**（见面、通话、亲自回复）、真人内容在信息流中的占比 |
| 商业 | 订阅转化率、单用户分身成本 / 单用户收入 |

**红线指标**：真人内容占比低于一半，或"等真人回我"触发率持续上升，说明分身在挤出真人，要立刻降低分身活跃度。

### 9.3 要验证的假设

1. **朋友是否接受和分身对话。** 可先做假门测试：真人手动扮演分身，观察朋友的反应和"等真人"的比例，不需要先做模型。
2. **用户会把授权交到哪一级。** 多数人是否永远停在 L0。如果是，产品就是一个"帮你写动态的工具"，价值要重估。
3. **分身内容能否被分辨，分辨出来后互动意愿降多少。** 对比"有标识的分身回复"和"真人回复"的后续互动率。
4. **单人阶段是否成立。** 零好友用户的 D7 留存决定冷启动能不能绕开 Path 的网络效应问题。
5. **分身是否促成了真人互动，还是替代了真人互动。** 对比有分身和无分身圈子的真人互动频次。

## 10. 与现有项目的复用

本方案和 AI 剧情聊天方案（[`ai-story-chat-redesign.md`](ai-story-chat-redesign.md)）共用一套底层，差别只在"角色效忠于谁"：

| 现有能力 | 剧情聊天中的用法 | 分身中的用法 |
|---|---|---|
| 角色圣经 | 编剧写死的虚构角色 | 用户自己的自我圣经，从对话和数据里学 |
| 关系状态 | 角色对玩家的好感、阶段 | 用户对每个朋友的圈层、自主等级、透露范围 |
| 剧情记忆 / 长期记忆 | 玩家做过的选择、聊过的事 | 用户的日记、事实、和每个朋友的历史 |
| 主动消息 | 角色按作息找玩家 | 分身的每日简报、"该你出面"提醒 |
| 安全层 | 出戏检测、尺度控制、危机识别 | 越界检测、承诺检测、冒充检测、危机识别 |
| Prompt 分层 + caching | 同 | 同，层 3 改为对象关系状态 |

原型 [`app/`](../app/README.md) 里的 prompt 组装、记忆提炼、主动消息三个模块可以直接抽出来复用。

## 11. 下一步

1. **假门测试**：找 2–3 个小圈子（每个 5–8 人），由真人手动扮演分身两周，验证 §9.3 的假设 1 和 3。
2. **自我圣经原型**：用现有角色圣经结构改一版，让 3–5 个内部用户建立自己的圣经，看"像不像我"能到什么程度。
3. **透明标识与分身日志的交互设计**：这是信任底线，在任何模型工作之前先把体验定下来。
4. **法务预审**：代表权、朋友数据、AI 披露三项。
5. 定下 MVP 后，从 `app/` 抽出 prompt 分层和记忆模块，搭分身版原型。
